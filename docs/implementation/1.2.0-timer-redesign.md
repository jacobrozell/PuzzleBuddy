# 1.2.0 timer redesign — implementation plan

**Branch base:** `feature/1.2.0-puzzle-timer` (commit `73ff967`)
**Spec it replaces:** [specs/planned/in-app-timer.md](../../specs/planned/in-app-timer.md). Update the spec in Phase 7.
**Audience:** an implementation agent. Do the phases in order. Each phase is one commit, and each commit builds, lints, and passes tests.
**Last updated:** 2026-10-28

Read [AGENTS.md](../../AGENTS.md) and [docs/swiftdata-migrations.md](../swiftdata-migrations.md) before you start.

---

## 1. Why

The timer on the branch works: start, pause, reset, one timer runs at a time, and it survives backgrounding. It is still only a stopwatch inside a `GroupBox`. Competing apps already offer more:

| Competitor | Timer features |
|------------|----------------|
| **Puzzle Tracker** (closest rival) | Pausable timer per puzzle; time per redo attempt |
| **Puzzlr** | Live per-session timer; "smart ETA" from real pace; time-per-piece stats |
| **Jvh Puzzle** | Full-screen "Puzzle Sessions" mode with pause/resume, quick piece-count updates, 30/60-minute goals, keep-screen-awake |
| **Hey Puzzlers** | "Precision timer" and "deep stats" |

To match them, and beat them on accessibility, Puzzle Buddy needs:

1. **Sessions.** Every start→pause span is saved, so people can see "4 sessions · 6 h 12 m" and fix a session they forgot to pause.
2. **Pace and ETA.** Use pieces and progress %, which the app already stores. No new user input is needed.
3. **A focus mode.** A full-screen clock that keeps the screen awake, with a quick progress update when you pause.
4. **The timer visible outside the detail screen.** A ticking list row, a floating mini-bar, a Live Activity with Dynamic Island, and Siri/Shortcuts.
5. **Recovery when someone forgets to pause.** No current competitor does this, so it is a differentiator.
6. **Timer data in completions and stats.**

## 2. Ground rules (read twice)

- Keep the existing semantics in `specs/planned/in-app-timer.md` unless this plan says otherwise:
  - one running timer at a time
  - leaving In-Progress pauses the timer
  - clock skew drops the open segment
  - completion prefill only fills empty logged time
  - Redo zeroes the timer
- Keep all time math in `PuzzleTimerSemantics`, pure and with a `now: Date` parameter. Views and the store call into it. Unit-test every new function there.
- Logging goes only through `AppLog.shared`. Every new event name and metadata key must go in `PuzzleAnalyticsEventMapping` (`App/Util/AppLogging.swift`) and in `docs/telemetry.md`. Never put a puzzle name or raw seconds in analytics; use buckets.
- No `print()`.
- Every new interactive element gets:
  - an `A11yID` constant in `DesignTokens.swift`
  - a 44pt minimum hit target
  - an accessibility label, plus a hint where needed
- Use `DS.Spacing`, `Brand.*` colors, `BrandPrimaryButtonStyle`, `BrandSecondaryButtonStyle`, and `BrandGroupBoxStyle`. Do not add hard-coded colors.
- Respect `accessibilityReduceMotion`: no pulsing unless reduce motion is off.
- Test at Dynamic Type `accessibility5`; use `ViewThatFits` or a stacked layout for large sizes, as the current card does.
- After adding files or targets: run `xcodegen generate`. Never edit the `.xcodeproj`.
- Run before every commit:
  ```bash

  Scripts/ci/run-tests.sh "platform=iOS Simulator,name=iPhone 16"
  ```
- If a test fails and you cannot work out why after two attempts, stop and report it. Never skip or disable a test.

## 3. Target UX (what "done" looks like)

### Puzzle detail (In-Progress)

The timer card moves **directly under the summary panel**, above progress. It is the main action while puzzling.

```
┌──────────────────────────────────────┐
│  Timer                     ● Running │  ← status chip (Running / Paused)
│                                      │
│            2:14:07                   │  ← large monospaced clock
│     This session 0:32:10 · Today 1:05│
│                                      │
│   [ ⏸ Pause ]        [ ⛶ Focus ]     │  ← primary + secondary buttons
│                                      │
│  ~410 pcs/hr  ·  ≈ 3 h 20 m left     │  ← pace/ETA (only when meaningful)
│  4 sessions  ›                       │  ← opens Sessions sheet
└──────────────────────────────────────┘
```

- **Reset** moves into the Sessions sheet (`…` menu → "Reset timer"), because it is rare and destructive.
- When the total is 0 and the timer is paused, the card shows a single **Start puzzling** button with a one-line explainer: "Track how long this puzzle takes. Runs in the background."

### Pause flow

When you tap Pause, a small sheet (`.presentationDetents([.height(…), .medium])`) offers **"Update progress?"**. It holds the existing progress slider, prefilled with the current %, plus **Save** and **Skip**. This keeps pace and ETA accurate. Settings has a toggle to turn the prompt off: `@AppStorage("timer.promptProgressOnPause")`, default `true`.

### Focus mode (full screen cover)

- Huge clock (`.system(size: …, design: .rounded)` with `minimumScaleFactor`), with the puzzle cover photo dimmed behind it.
- Pause/Resume, progress quick-steps (−5 / +5 %), and Done.
- `UIApplication.shared.isIdleTimerDisabled = true` while the screen is shown, reset to `false` in `onDisappear`. Settings has a toggle for this: `timer.keepScreenAwake`, default `true`.
- Optional session goal: chips for 30 m, 60 m, 90 m, and none. When the goal is reached, play a haptic (`.sensoryFeedback(.success, …)`) and show a banner. The timer **does not** stop.
- Works in landscape. Use `AdaptiveLayout` helpers if they fit.

### Sessions sheet

- A list grouped by day: start time–end time and duration for each session; manual entries are marked "Added manually".
- Swipe to delete, and tap to edit start and end with `DatePicker`. Validation: end must be after start, the session cannot be in the future, and it must not overlap another session.
- **Add time** button for "I forgot to start it": a duration picker that creates a manual session ending now.
- `…` menu with **Reset timer**, using the existing confirmation copy.

### Forgot-to-pause recovery

On app foreground (`scenePhase == .active`), if a timer has been running for **longer than 4 hours with no interaction**, show an alert:

> "Your timer for *Puzzle* has been running 9 h 12 m. Keep it, or stop it at the last time you used the app?"

- **Keep:** do nothing.
- **Stop at last use:** close the session at `lastInteractionAt`.

Store the 4-hour threshold as a constant in `PuzzleTimerSemantics`.

### Outside the detail screen

- **List row:** the running puzzle shows a live `Text(timerInterval:countsDown: false)` next to the timer icon. Paused puzzles with time show a static total in secondary text.
- **Mini-bar:** while any timer runs, a compact bar sits above the tab bar on the Puzzles tab. It shows the cover thumbnail, name, a ticking clock, and a Pause button; tapping it opens the detail.
- **Live Activity + Dynamic Island:** puzzle name, ticking clock, progress %, and Pause/Resume buttons (interactive via `LiveActivityIntent`).
- **App Shortcuts:** "Start puzzle timer", "Pause puzzle timer", and "How long have I been puzzling?"

### Completion and stats

- Completion history rows show "Timed: 6 h 12 m · 4 sessions" when sessions exist for that attempt.
- Detail metrics show pieces/hour from the timer when the timer is the source of the logged time.
- The Stats tab gets a **Puzzling time** card with these figures; omit the card when there are no sessions:
  - total timed hours
  - number of sessions
  - average session length
  - longest session
  - a sessions-per-week bar chart for the last 8 weeks (Swift Charts)

## 4. Data model

### New `@Model` — `App/Helpers/PuzzleTimerSessionRecord.swift`

```swift
@Model
final class PuzzleTimerSessionRecord {
    @Attribute(.unique) var id: UUID
    var puzzleID: UUID
    var startedAt: Date
    var endedAt: Date
    var isManual: Bool = false
    /// nil = belongs to the current (unfinished) attempt.
    var completionID: UUID?
    var progressAtStart: Int?
    var progressAtEnd: Int?
}
```

Add a matching domain struct, `PuzzleTimerSession`, with `toDomain()`, `init(from:)`, and `apply(from:)`, following `PuzzleCompletionRecord`. Add `Puzzle.timerSessions: [PuzzleTimerSession]`, loaded the same way `completions` is loaded.

### New field on `PuzzleRecord` / `Puzzle`

`timerLastInteractionAt: Date?`

Update it on start, pause, progress edit, and app foreground while the detail screen is visible. It is used by forgot-to-pause recovery.

### Keep the existing fields

- `timerRunningSince` is still the open session's anchor.
- `timerAccumulatedSeconds` becomes a **cache** of the sum of closed sessions where `completionID == nil`. Recompute it from sessions on every session write. Never increment it on its own.

### Lifecycle rules

| Event | Sessions | Cached fields |
|-------|----------|---------------|
| Start | none yet (open anchor only) | `runningSince = now`, `lastInteractionAt = now` |
| Pause | insert a closed session `[runningSince, now]` with progressAtStart/End; drop sessions shorter than 5 s | `runningSince = nil`, recompute accumulated |
| Starting B pauses A | as for Pause, on A | as for Pause, on A |
| Leaving In-Progress | as for Pause | as for Pause |
| Mark Completed | close any open session, then set `completionID` on all `completionID == nil` sessions to the new completion's id | accumulated = 0 after stamping, because the completion row now owns the time; the logged-time prefill must read the total **before** stamping |
| Redo | none (old sessions keep their completionID) | both zero, as today |
| Undo completion | clear `completionID` on that completion's sessions | recompute accumulated |
| Reset | delete sessions where `completionID == nil` | both zero |
| Delete puzzle / Delete All Data | delete all its sessions | — |
| Clock skew | drop the open segment (no session) | as today |

**Undo note:** today's spec says undo keeps the timer paused with its time. After this change, undo un-stamps the sessions, so the time comes back. This is an intentional behavior change; record it in the spec.

### Backup JSON (`PuzzleCollectionExporter` / `PuzzleCollectionJSONImporter`)

Add an optional `timerSessions` array per puzzle. When the key is missing, use an empty array. Round-trip it in `PuzzleCollectionBackupTests`. Leave CSV unchanged.

### Delete paths

Grep for every place that deletes `PuzzleCompletionRecord` or `PuzzlePhotoRecord`, including "Delete All Data" and the `FriendRecord` wipe in commit `4e4f04a`. Delete `PuzzleTimerSessionRecord` there too. Add a test.

### Phase 2 — Pace and ETA (pure logic)

Add `PuzzleTimerSemantics.pace(pieces:progressPercent:seconds:) -> (piecesPerHour: Int, remainingSeconds: Int?)?`

- Return nil unless `pieces > 0`, `progressPercent >= 5`, and `seconds >= 600`.
- `placed = pieces * progress / 100`
- `pph = placed / hours`
- `remaining = (pieces - placed) / pph`
- Remaining is nil at 100%.
- Round pph to the nearest 5 for display.

Labels:
- `"~410 pcs/hr"`
- `"≈ 3 h 20 m left"`
- Spoken: `"About 410 pieces per hour, about 3 hours 20 minutes left"`

Reuse `PuzzleDetailMetrics` formatting if it already has a pieces-per-hour formatter (check `App/Helpers/PuzzleDetailMetrics.swift`); do not duplicate it.

**Tests:** zero pieces, under 5 %, under 10 min, 100 %, and normal cases.

## 6. Out of scope (do not build)

- Countdown timers, Pomodoro cycles, or team/shared timers
- Notifications. The app has no notification permission today; adding one needs a separate decision.
- Apple Watch app or home-screen widget. The `home-screen-widget.md` spec is separate, but the Phase 6 widget target can host it later.
- Cloud sync of sessions
- Changing how collection stats sum `estimatedTimeSpent`. Logged time stays the source of truth for existing stats; the new card only reads sessions.
