# 1.1.1 — Split oversized files

**Target:** 1.1.1 (after 1.1.0 ships)  
**Branch (when started):** `release/1.1.1` or a short-lived `chore/file-split` off `main`  
**Trigger:** 1.1.0 polish left `PuzzleList` / `PuzzleStore` even larger. The 1.1.0 delta was ~1k lines because those files already absorb every new chip, sheet, and store API.

## Problem

These files are the places new work lands by default. They compile and test, but reviews and follow-on features keep getting more expensive.

| File | ~Lines (2026-09-25) | Smell |
|------|--------------------:|-------|
| `App/Views/PuzzleViews/PuzzleList.swift` | 1,373 | God view: layout + toolbar + filters + scan + empty states + tag sheet |
| `App/Views/PuzzleViews/CollectionStatsView.swift` | 856 | One screen owns every stats section + chart + cards |
| `App/Helpers/PuzzleStore.swift` | 800 | CRUD + completions + undo + photos + loans + demo + import |
| `App/Views/PuzzleViews/PuzzleForm.swift` | 617 | Sheet wrapper + full form + submit button |
| `App/Views/PuzzleViews/PuzzleDetail.swift` | 488 | Banner + edit mode + `DetailView` stats dump |
| `App/Util/DesignTokens.swift` | 442 | Brand tokens + button styles + a growing `A11yID` enum |

1.1.0 helpers (`WhatsNewPrompt`, `OnboardingCopy`, `CompletionUndoSemantics`, `PuzzleCompletionHistoryCopy`) are the pattern to copy — small, testable, no schema.

## Goals

1. **Move code, don’t change behavior.** Same UI, same store APIs, same identifiers, same events.
2. **Give new work a home** so 1.2 features (timer, barcode attach, tag cloud) don’t grow `PuzzleList` / `PuzzleStore` again.
3. **Keep AppTests green** after each extract. No marketing-screenshot refresh unless a layout actually changes (it shouldn’t).

## Non-goals

- New user-facing features
- SwiftData schema / migration
- New Analytics events
- Rewriting navigation (split view vs push)
- Changing 1.1.0 iOS 18 behavior (sidebar-adaptable tabs, zoom transitions, `presentationSizing`) — move those as-is
- “Clean architecture” layers or a new DI container
- Splitting files that are already under ~350 lines

## Size guardrails (soft)

After 1.1.1, prefer:

| Kind | Soft max | If you exceed it |
|------|---------:|------------------|
| SwiftUI screen | ~400 | Extract a section or sheet |
| `PuzzleStore` type | ~400 | Extension file or focused helper |
| New helper | ~150 | You’re doing too much in one type |

Do **not** add a linter gate in 1.1.1. Revisit if a file crosses 1,000 again.

## Sprint order

One PR per phase if possible. Stop after any phase — leftover phases stay on this doc.

### 1. `PuzzleList` (do first)

Highest cost, most 1.1.0 additions (overdue chip, filter sheet).

| Extract | Suggested file | Contents today |
|---------|----------------|----------------|
| Filter chrome | `PuzzleListFilters.swift` | Chips, filter sheet, sort menu, `clearSecondaryFilters`, empty-state copy |
| Add / scan chrome | `PuzzleListActions.swift` | FAB, add menu, toolbar scan / shopping / pick-next |
| Scan handoff | keep using `BarcodeScannerSheet` / `QuickAddPuzzleSheet`; move `handleScannedBarcode` + `beginQuickAdd` next to them or into `PuzzleListScanFlow.swift` | |
| Tag picker sheet | `PuzzleTagFilterSheet.swift` | Nested tag-search sheet already at the bottom of `PuzzleList.swift` |

`PuzzleList` keeps: `displayedPuzzles`, layout (compact / regular / split), collection vs grid, navigation, delete.

**Done when:** `PuzzleList.swift` is under ~500 lines and adding a filter chip does not require scrolling past scan/FAB code.

### 2. `PuzzleStore` completions

Undo + history already have semantics types. Pull mutations into one place.

| Extract | Suggested file | Contents |
|---------|----------------|----------|
| Completions | `PuzzleStore+Completions.swift` | `appendCompletion`, `deleteCompletion`, `updateCompletion`, `undoLastCompletion`, `reconcileCompletions`, pending-undo helpers |
| Photos | `PuzzleStore+Photos.swift` (optional same sprint) | `syncPhotos`, legacy cover migration |

Public method names stay on `PuzzleStore` (extensions). Call sites must not change.

**Done when:** `PuzzleStore.swift` is mostly fetch/add/update/delete + loan/demo/import.

### 3. `CollectionStatsView` sections

`YearActivityChart` and `StatHighlight` already live at the bottom of the same file — move them out, then one file per section group.

| Extract | Suggested file |
|---------|----------------|
| Hero + highlight strip | `CollectionStatsHero.swift` |
| Year activity | `CollectionStatsYearActivity.swift` (chart stays with it) |
| Breakdown cards (pace, shop, tags, piece range) | `CollectionStatsBreakdowns.swift` |
| Shared `statCard` / `breakdownRow` | `CollectionStatsCards.swift` |

`CollectionStatsView` keeps: empty state, milestone banner, `onAppear` year validation.

**Done when:** the screen file is a short `VStack` of sections.

### 4. `PuzzleForm` / `PuzzleDetail` (if time)

Lower urgency — they grow slower than the list.

- `PuzzleFormInternal` sections (identity, dates, loan, metadata, photos) → `PuzzleFormSections.swift`
- `DetailView` stats rows → `PuzzleDetailStats.swift`; leave undo banner + edit chrome on `PuzzleDetail`

### 5. `A11yID` (optional)

If `DesignTokens.swift` is still the dump for every identifier:

- Move `enum A11yID` to `App/Util/A11yID.swift`
- Leave `Brand`, `DS`, and button styles in `DesignTokens.swift`

## Rules while splitting

1. **No `project.yml` source-list edits** — `App/` is a folder glob; new files are picked up after `xcodegen generate`.
2. **Keep `A11yID.*` strings identical.** UI tests and VoiceOver contracts depend on them.
3. **Don’t rename `PuzzleStore` methods** just to look tidy.
4. **Don’t move SwiftData `@Model` types** in this sprint.
5. After each phase: `xcodegen generate` + `xcodebuild -scheme PuzzleBuddy -only-testing:AppTests test`.

## Verification

```bash
cd PuzzleBuddy && xcodegen generate
xcodebuild -scheme PuzzleBuddy -destination 'platform=iOS Simulator,name=iPhone 17' \
  -only-testing:AppTests test
```

Manual (only if a extract accidentally changes layout):

1. Collection list: filters, overdue chip, FAB, scan, empty states, iPad + landscape.
2. Detail: completion swipe / undo banner still present.
3. Stats tab: cards and year chart unchanged.
